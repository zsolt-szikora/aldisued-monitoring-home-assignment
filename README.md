## 📂 Project Structure (expected)
```
src/main/java/com/aldisued/iot/monitoring
├── controller   REST endpoints
├── dto          DTOs
├── entity       JPA entities
├── exception    Domain exceptions
├── messaging    Kafka listeners for incoming messages
├── repository   Spring Data JPA repositories
└── service      business logic

src/test/java/com/aldisued/iot/monitoring
├── controller   Additional controller test
└── tasks        provided task tests
```

The database schema is dropped and re-generated by Hibernate from the entity classes on each start of the application.

## Running Locally

Prerequisites: Java 21 and Docker.

Run the tests (PostgreSQL is started automatically via Testcontainers):

```bash
./mvnw test
```

Start the application against the PostgreSQL database from `docker-compose.yml`:

```bash
docker compose up -d
SPRING_DATASOURCE_URL=jdbc:postgresql://localhost:5432/monitoring \
SPRING_DATASOURCE_USERNAME=monitoring_user \
SPRING_DATASOURCE_PASSWORD='IOT123!' \
SPRING_KAFKA_LISTENER_AUTO_STARTUP=false \
./mvnw spring-boot:run
```

No Kafka broker is part of the docker-compose.yml, so the Kafka client keeps logging warnings;
`SPRING_KAFKA_LISTENER_AUTO_STARTUP=false` make the listeners start stopped to avoid log spamming. 

To see what the app offers over REST, springdoc-openapi-starter-webmvc-ui was added. See
http://localhost:8080/swagger-ui.html for more details.
